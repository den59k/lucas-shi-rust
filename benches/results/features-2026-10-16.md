# Detection benchmark: numerical fixes

Empirical host measurements on 2026-10-16, `aarch64-apple-darwin`, stable Rust
1.99.0 (`b940084d7`, LLVM 23.1.1). Build settings: opt-level 3, LTO enabled,
1 codegen unit, default host CPU target, no `target-cpu=native`.

Before: `f34658f98bee75e9535062513d4603ec2b7f1b14` (`main`). After: the uncommitted
`fix-shi-tomasi-numerics` working tree. Both binaries used the exact same
`benches/features.rs`, input bytes, parameters, lockfile, and toolchain. They
were compiled in separate target directories; binary hashes were checked to
exclude reuse of a stale artifact. Source, harness, input, and binary hashes
are recorded in [the machine-readable results](features-2026-10-16.json).
The measured snapshot still contained the subsequently removed redundant
`is_finite()` guard in the quality filter; the recorded hashes identify that
snapshot. The timings have not been remeasured after that cleanup.

Each case used 50 samples, 1 s warm-up, and 3 s target measurement time. Builds
were finished before timing. Runs were sequential, alternating before/after per
input. The table consistently uses Criterion's mean estimate and bootstrap
95% confidence interval; a console slope estimate can differ from this mean.
The exact CPU model, background load, and clock frequency were not recorded.
These results describe this host run, not a worst-case execution time.

Quality was 0.05, minimum distance 8 px, grid 6x4, and budget 5 points per cell.
Top-up used 24 fixed existing points, one at each cell center. Image preparation,
corner-count reporting, and console/file output were outside timing. Each call
includes the detector's internal allocations and deallocations.

## Interpretation

The fixed detector has lower mean whole-call times in these cases. This is the
combined effect of the eigenvalue, box-filter, zero-response, and spacing fixes.
The output counts change too, so sorting and spacing can perform different
amounts of work. These measurements do not isolate the cost of f64 arithmetic.
On the flat image, the original detector reports 5,520 false corners through
the plain API, while the fixed detector correctly reports none. Counts for the
example image change from 867 to 54; count alone does not assess feature quality
on that scene. The synthetic textures produce more corners after the fixes.

## Reproduction

See [the benchmark instructions](../README.md). Use the same harness against
both source revisions, separate target directories, and a common
`CRITERION_HOME` for baseline comparison. The normal entry point is:

```sh
cargo +stable bench --locked --bench features
```
